# ADR-0016: 접근성 검증 마무리 (BENCHMARK.md 5.20 잔여분)

- **상태**: 채택, 구현 완료 (2026-08-13 — 캔버스 목록 뷰 + 신규 화면 axe-core 재검증. 스크린리더 실기 테스트는 환경적 한계로 여전히 미완, IMPLEMENTATION_REPORT.md §24)
- **날짜**: 2026-08-13
- **근거 문서**: BENCHMARK.md 5.20, 2026-08-12 접근성 감사(axe-core + 수동 키보드 테스트)

## 배경

5.20은 2026-08-12에 axe-core + 수동 키보드 테스트로 실제 감사를 수행해 critical/serious 위반을 모두 고쳤다. 그때 명시적으로 범위 밖에 남긴 두 가지가 있다:

1. **서브그래프 시각화(`ImpactGraph.tsx`, Cytoscape.js 캔버스)의 그래프 노드/엣지는 canvas 렌더링이라 키보드로 순회할 수 없다** — "별도의 목록 보기 대안 UI가 필요한 더 큰 설계 과제"로 미뤘다.
2. **스크린리더 전체 시나리오(VoiceOver/NVDA 실기) 테스트를 아직 하지 않았다.**

또한 그 감사 이후 두 화면이 새로 생겼다 — 구조 탭(`StructureTree.tsx`, ADR-0013)과 검토 탭의 사각지대 섹션(ADR-0011) — 이들은 2026-08-12 감사 대상에 없었으므로 회귀가 없는지 다시 확인해야 한다.

## 결정 1 — ImpactGraph에 키보드 접근 가능한 "목록 보기" 추가 (canvas는 그대로 둔다)

Cytoscape canvas 자체를 키보드 순회 가능하게 만드는 건 범용적으로 어렵다(canvas는 DOM 트리가 아니라 픽셀이라 스크린리더가 개별 노드를 인식할 방법이 없다) — 그래서 canvas를 고치는 대신, **이미 fetch된 같은 subgraph 데이터(`data.entities`/`data.relationships`)를 키보드로 순회 가능한 목록으로도 렌더링**한다. 새 API 호출은 없다.

- `ImpactGraph.tsx`에 "그래프 | 목록" 토글(두 `<button role="tab">` 정도)을 추가한다. 기본은 기존과 동일한 그래프 뷰(회귀 없음), 목록 뷰를 선택하면 canvas 대신 `data.entities`를 노드 목록(종류·이름·root 여부)으로, `data.relationships`를 엣지 목록(source→target, type, resolution)으로 각각 `clickableRowProps`(기존 공용 유틸)로 렌더링한다.
- 목록의 노드 행 클릭 = 캔버스의 `onSelectNode`와 동일 동작(엔티티로 이동), 엣지 행 클릭 = `onSelectEdge`와 동일 동작(Evidence 패널 오픈) — 콜백을 그대로 재사용해 캔버스와 목록이 다른 동작을 하지 않게 한다.
- 그래프 툴바(방향/depth/타입/resolution 필터)는 두 뷰가 공유한다 — 필터링된 같은 `data`를 다르게 그릴 뿐이다.

## 결정 2 — 새로 생긴 화면 2개에 axe-core 재실행, 스크린리더 실기 테스트는 범위 밖으로 명시

2026-08-12 감사와 같은 방법(axe-core WCAG 2 A/AA + 실제 Tab 순회)을 구조 탭과 검토 탭의 사각지대 섹션에 적용한다. 위반이 나오면 그 자리에서 고친다(2026-08-12와 같은 패턴).

**스크린리더 실기 테스트(VoiceOver/NVDA)는 이번에도 하지 않는다** — 지난번과 이유가 다르다: 이번엔 "설계 과제라 미룬다"가 아니라 **이 작업이 실행되는 환경(헤드리스 CLI 세션)에는 실제 GUI 스크린리더를 구동할 방법이 없다**는 환경적 한계다. axe-core는 WCAG 규칙 위반을 정적으로 잡아주지만 "스크린리더 사용자가 실제로 이 화면을 어떻게 경험하는가"는 대체할 수 없다 — 이 갭은 감춰서는 안 된다. IMPLEMENTATION_REPORT.md와 BENCHMARK.md에 "자동 검사로 대체 불가능한 범위"로 명시하고, 실제 데스크톱 환경에서 사람이 VoiceOver/NVDA로 확인하기 전까지는 [부분 해결] 상태를 유지한다.

## 하지 않는 것

- Cytoscape canvas 자체를 접근 가능하게 만들려는 시도(ARIA live region으로 캔버스 내용을 흉내내기 등)는 하지 않는다 — 목록 보기라는 병행 대안이 더 정직하고 유지보수 가능하다.
- 스크린리더 실기 테스트를 시뮬레이션이나 휴리스틱으로 "완료"라고 표시하지 않는다.
- `StructureTree`/`Review` 외 기존에 이미 감사·수정된 화면(2026-08-12 대상 6개)은 다시 손대지 않는다 — 회귀가 없다면 그대로 둔다.

## 구현 순서

1. `ImpactGraph.tsx`: 그래프/목록 토글 + 목록 뷰 렌더링(공용 콜백 재사용).
2. Playwright + axe-core로 구조 탭, 검토 탭(사각지대 섹션), ImpactGraph 목록 뷰 신규 검증 + 목록 보기에서 Tab만으로 노드/엣지 선택까지 되는지 수동 키보드 시나리오 확인.
3. 위반 발견 시 그 자리에서 수정.
4. BENCHMARK.md 5.20 상태 갱신(완전 해결이 아니라 스크린리더 실기 테스트가 남아있다는 사실을 그대로 유지), IMPLEMENTATION_REPORT.md 부록 추가.
