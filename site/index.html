코드를, 파일이 아니라
관계로 읽는다.

ContextSource는 TypeScript 소스를 Entity · Relationship · Evidence 그래프로 변환합니다. 모든 관계는 코드 근거(Evidence) 없이는 저장조차 되지 않고, 사람이 쓰는 Web UI와 AI 에이전트가 붙는 MCP 서버가 정확히 같은 그래프를 봅니다.

문제의식

"정의로 이동"은 관계를 보여주지 않는다

IDE의 참조 찾기와 grep은 코드가 어디서 등장하는지는 알려주지만, 그 등장이 얼마나 확실한지, 왜 연결됐다고 판단했는지는 답하지 않습니다. PR을 검토하거나 AI 에이전트에게 "이 함수를 고치면 무엇이 흔들리는가"를 물을 때 필요한 건 텍스트 매칭이 아니라, 근거를 가진 구조화된 관계입니다.

ContextSource는 소스를 정적으로 분석해 Entity(코드의 명사) · Relationship(코드의 동사) · Evidence(그 관계가 실재한다는 증거)로 바꾸고, 이 그래프를 사람과 AI가 같은 Query 계층으로 조회합니다.

grep텍스트 매칭 — 구조 모름, 근거 없음
참조 찾기occurrence 목록 — 신뢰도 구분 없음
ContextSourceEntity·Relationship·Evidence — static/inferred 신뢰도 + 근거 코드
핵심 모델

세 가지 개념으로 코드 전체를 표현한다

새 개념을 늘리지 않는다 — Entity 6종, Relationship 5종, 그리고 그 둘을 잇는 Evidence 하나로 충분하다.

Entity

코드의 명사. 파일·클래스·인터페이스·함수·메서드, 그리고 프로젝트 밖 패키지를 하나로 접은 External Module.

fileclassinterfacefunctionmethodexternal_module

Relationship

코드의 동사. 확정된(static) 관계와 규칙으로 추론한(inferred, 낮은 confidence) 관계를 구분해 저장한다.

DECLARESIMPORTSCALLSIMPLEMENTSEXTENDS

Evidence

그 관계가 실재한다는 증거 — 파일:라인과 코드 스니펫. 스키마 수준에서 Evidence 없는 Relationship은 저장 자체가 불가능하다.

file:linesnippetrevision
기능

그래프 위에서 실제로 무엇을 할 수 있나

01

변경 영향 분석

Entity 하나를 바꾸면 무엇이 영향받는지, 후보를 랭킹·이유·경로·신뢰도와 함께 보여준다. Git diff와 연결해 "이번 커밋에서 뭘 검토해야 하는가"까지 답한다.

직접 영향 → 간접 영향 → 관련 테스트로 보이는 파일 순서로 정리
02

Git Diff 기반 증분 분석

바뀐 파일과 그 역방향 의존 파일만 다시 분석한다. 28만 줄 규모 실측에서 전체 재분석 3.7–4.1초, 15개 파일 변경 후 증분 재분석 3.5초.

역방향 import 전이적 폐포까지 추적 — 2-hop 이상 떨어진 재분석 대상도 놓치지 않음
03

정직한 신뢰도

확정된 관계(static)와 추론된 관계(inferred)를 confidence로 구분하고, 그마저 확정하지 못한 참조는 버리지 않고 "사각지대"로 따로 기록한다.

false positive를 만들 바엔 "모른다"고 말한다 — 그래프가 완전하다고 오해하게 두지 않는다
04

자동 감지 프로젝트 카탈로그

package.json을 읽어 기술 스택을 자동 태깅하고, 태그 교집합만으로 유사 프로젝트를 찾는다 — 임베딩도, Vector Search도 쓰지 않는다.

코드 관계 그래프의 보조 기능으로 의도적으로 얕게 유지 — 카탈로그 제품이 되려는 게 아니다
Shared Context

사람과 AI가 서로 다른 그래프를 상상하지 않는다

TypeScript 소스 → Query 계층 / SQLite →
Web UI · 사람 MCP 서버 · AI 에이전트
＝

Web UI를 보는 개발자와 MCP로 붙은 AI 에이전트는 같은 Query 함수, 같은 SQLite 데이터를 조회합니다. AI가 보는 "영향 범위"와 사람이 화면에서 보는 "영향 범위"는 항상 같은 계산 결과입니다.

아키텍처

4개 계층, 외부 서비스 의존 없음

소스 코드는 로컬을 떠나지 않는다 — 별도 그래프 DB나 외부 API 호출이 없다.

01 · 분석

TypeScript Compiler API

AST와 TypeChecker로 Entity/Relationship을 추출. static/inferred를 여기서 판정한다.

02 · 저장

SQLite (내장)

Node 22.5+의 node:sqlite 내장 모듈. 별도 DB 프로세스나 서버가 필요 없다.

03 · 조회

HTTP API

Express 기반 Query API. 전체 그래프 덤프 없이 항상 범위가 있는 조회만 제공한다.

04 · 소비

Web UI · MCP

React+Cytoscape 웹 화면과, AI 에이전트를 위한 읽기 전용 MCP(stdio) 서버.

Node.js ≥ 22.5.0 · SQLite 파일 하나 · Docker Compose 또는 make로 로컬 기동

있는 그대로

ContextSource는 단일 작성자가 만든 0일차 프로젝트입니다. Sourcegraph·CodeQL·Joern 같은 수년간 검증된 도구를 흉내 내려는 게 아니라, 로컬에서 곧바로 실행되는 Evidence 기반 TypeScript 변경 영향 탐색기로 시작합니다.

모든 설계 결정은 ADR 12건으로 기록되어 있고, 왜 어떤 기능(예: 범용 Query 언어, Vector Search)을 지금 넣지 않았는지도 그대로 남겨둡니다.

시작하기

3줄이면 로컬에서 뜬다

$ git clone https://github.com/peterica/context-source
$ cd context-source
$ docker compose up --build
→ http://localhost:9090 에서 Web UI 확인

Docker 없이: make setup && make run-api && make run-web
